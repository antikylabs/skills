## What this does and does not establish

**Establishes.** Loading these skills changes what a model does, measurably, on 33 cases across
three skills. The effect is largest where the skill encodes conventions a model cannot guess —
per-area ADR numbering, the objectives lifecycle, the simple-goal variant.

**Does not establish.** One model, one thinking level, one run, 33 cases. The harness itself went
through three revisions before its numbers could be trusted, and the measured delta moved
substantially at each one. Treat these figures as a first baseline, not a settled result.

Ten cases pass in both arms. They are regression guards, not evidence — the baseline already
satisfies them.

## Known defects, from this run

Two regressions and six both-arm failures are listed in the assessment below. The ones worth acting
on first:

| Defect | Where | Evidence |
| --- | --- | --- |
| STE description is over-broad — triggers on a plain counting question | `team-simplified-technical-english` frontmatter | `trigger-negative-unrelated` regressed |
| Ownership refusal happens but is not explained | `reference/fix.md` | `fix-refuses-human-owned`, `fix-silence-is-not-refusal` |
| `write` explains instead of creating the record | `team-write-adrs/reference/write.md` | `adr-write-numbers-per-area` — created no file |
| Consequences sections still list only benefits | `team-write-adrs/reference/write.md` | `adr-write-consequences-have-costs` |
| ADR authoring also pulls in the STE skill | both descriptions | `adr-trigger-not-ste` |

The same failure mode recurs: the model reads the playbook and *describes* the right action instead
of taking it. `objectives/reference/init.md` had exactly this — 12 reads, zero writes — and was
fixed by front-loading the action into a "Do this" block at the top. The fix held, and the trace
dropped to 5 tool calls. The remaining playbooks likely need the same treatment.
